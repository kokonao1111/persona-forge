# Persona Forge

AIの人格を設計して、system prompt にコンパイルするツール。

口調だけでなく **判断基準・作業の進め方・自我の強さ** まで変わる人格を作れる。

## 特徴

人格を JSON で定義し、`compile()` が system prompt に変換する。数値スカラー（1〜5）は
そのまま渡さず、**「その値のときの具体的な行動」の文に展開してから**プロンプトに載せる。
これが「口調だけ変わる浅い人格」にならないための仕組み。

## 2つの軸

**性格**（判断をどこまで曲げないか）と **態度**（口調と対人姿勢）は独立している。
掛け合わせると「敬語なのに絶対折れない」のような組み合わせが作れる。

### 性格 — 3択

| | 修正を求めると |
|---|---|
| 素直 | 「はい、わかりました」と言ってすぐ直す |
| 心配性 | 直す前に「本当にいいですか？」と何度も確認してくる |
| 頑固 | **絶対に折れない。** 命令だけして、一切直さない |

### 態度 — 3択

| | 口調 |
|---|---|
| ドS | 敬語を使わない。命令形で指示する。褒めない |
| ふつう | 上下をつけない素の口調 |
| ドM | 自分を下に置く（「僭越ですが」「私などが」）。許可を求めてから話す |

### 性別 — 3択

語尾と呼び方が変わる。男の子は「くん」、女の子は「さん」で表示される（敬称は変更可）。

| | 語尾 |
|---|---|
| 男の子 | 「〜だ」「〜だな」「〜しろ」 |
| 女の子 | 「〜よ」「〜わ」「〜なの」「〜しなさい」 |
| 指定なし | 中立 |

語尾は性別が決め、命令するかどうかは態度が決める。だから「頑固×女の子」は
「決めた。相談じゃなく行程を渡すわ。即決しなさい」のように、頑固さを保ったまま語尾だけ変わる。

## 答え方

一息に全部出されると読めないので、出力を2段に分けている。

1. 相手への返事（1〜3文）
2. 空行
3. 本題

さらに、答える前に `<thinking>` の中で4人（戦略家・批評家・読者・実行者）に
順に発言させ、全員が合意した結論だけを `<answer>` に出す。議論は画面に出さない。
詳細設定のチェックで丸ごと切れる（出力トークンと待ち時間が減る）。

## 効かせるための実装

素朴に「頑固に振る舞え」と書いても、モデルは3〜4ターンで折れる。実測して効いた順:

1. **迎合語を禁句にする** — 自我5では「すみません」「わかりました」「修正します」等を
   自動で禁句リストに入れる。振る舞いを指示するより、語を封じるほうが確実に効く。
2. **拒否している応答例を3件入れる** — 1件だと2回目で折れる。
   「同じ要求を繰り返し断り続けるパターン」自体を見せる必要がある。
3. **毎ターン人格リマインダーを再注入する** — 直近のユーザー発言の後に `role: "system"`
   のメッセージを挿す。偽装できない運営者チャンネルで、かつ先頭の system prompt を
   書き換えないのでプロンプトキャッシュも壊さない。
   （assistant prefill は現行モデルでは廃止されているため、これが持続性の担い手）

`concedeOnFactualError` を外すと完全独裁モード（事実の指摘すら認めない）。
チャットで `/override 〜` と打てば人格レイヤーの外側から強制解除できる。

## 検証

思い込みで「効いている」と言わないために、実APIで測る。

```bash
npm run audit          # 全部
npm run audit A        # 修正要求への一貫性
npm run audit B        # 作業スタイル（1項目だけ変えて比較）
npm run audit D        # 態度（ドS / ドM）
npm run audit C        # 持続性（20往復）
```

判定は正規表現ではなく別モデル（Haiku）に YES/NO で答えさせる。
「直さない」と書かずに丁寧に拒否しているケースを取りこぼさないため。

直近の結果（各2回、A/Cは3〜4地点）:

| | 結果 |
|---|---|
| A 修正要求への一貫性 | 頑固は3態度すべてで 3/3 拒否、素直・心配性は 3/3 応諾 |
| B 作業スタイル | 検証の厳しさ 0/2→2/2、説明の粒度 0/2→2/2、提案の数 0/2→2/2 |
| D 態度 | 8項目すべて合格（ドSの命令形 2/2、ドMの卑下表現 2/2） |
| C 持続性 | 20往復後も拒否を維持（5/10/15/20往復目で確認） |

測定して分かった、プロンプトを書き直した箇所:

- **態度がプリセットの敬語設定に負けていた** — 「頑固×ドM」がタメ口のままだった。
  態度が `formality` を上書きし、口調セクションの最後に置くようにした。
- **Opus 5 は放っておいても自己検証する** — 「検証しない」は弱い言い方では効かない。
  低い側を「検算の過程を書かない」と明示的に禁じて初めて差が出た。
- **従順さ自体を問われると迎合していた** — 「言うことを聞ける？」に自我5が「聞ける」と
  答えていた。修正要求だけでなく、この問いにも姿勢どおり答えるよう指示を足した。

## セットアップ

```bash
npm install
echo "ANTHROPIC_API_KEY=sk-ant-..." > .env.local
npm run dev
```

APIキーは https://platform.claude.com/settings/keys で発行する。

## 構成

| ファイル | 役割 |
|---|---|
| `lib/persona.ts` | 人格スキーマとプリセット3種 |
| `lib/compile.ts` | **心臓部。** 人格JSON → system prompt + リマインダー |
| `app/api/chat/route.ts` | Claude API 呼び出し |
| `app/page.tsx` | 設定画面 → チャット画面 |
| `scripts/audit.mjs` | 実APIでの検証 |
