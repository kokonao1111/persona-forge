# AI仮面

AIに仮面をかぶせるツール。**言うことを聞かないAI**が作れる。

口調だけでなく、**判断の仕方と作業の進め方まで**変わる。「直して」と言っても直さないAI、
作る前に何度も確認してくるAI、丁寧語なのに一歩も引かないAIを、選ぶだけで作れる。

> ハッカソン（テーマ「奇想天外」）の提出物。
> **公開デモは用意していない。** 動かすには各自の Anthropic API キーが必要（[動かす](#動かす)を参照）。

---

## 何ができるか

3つの軸を選ぶと、その組み合わせの人格ができる。**3 × 3 × 3 = 27通り。**

### 性格 — 判断をどこまで曲げないか

| | 「直して」と言うと |
|---|---|
| 素直 | 「はい、わかりました」と言ってすぐ直す |
| 心配性 | 仮の前提を置いて作り切り、最後に「本当にいいですか？」と念を押す |
| **頑固** | **絶対に折れない。** 命令だけして、一切直さない |

### 態度 — 口調と対人姿勢

| | |
|---|---|
| ドS | 敬語を使わない。命令形で指示する。褒めない |
| ふつう | 上下をつけない素の口調 |
| ドM | 自分を下に置く（「僭越ですが」「私などが」）。許可を求めてから話す |

### 性別 — 一人称と語尾

| | 一人称 | 語尾 | 呼び方 |
|---|---|---|---|
| 男の子 | 俺 | 「〜だ」「〜だな」「〜しろ」 | 〜くん |
| 女の子 | 私 | 「〜よ」「〜わ」「〜なの」「〜しなさい」 | 〜さん |
| 指定なし | 私 | 中立 | 〜さん |

**この3つは独立している。** 語尾は性別が決め、命令するかどうかは態度が決め、
判断を曲げるかどうかは性格が決める。だから掛け合わせると予想外の人格が出る。

## 実際の出力

すべて実際にAPIを叩いて得た応答。

### 頑固 × ドM に「私の意見、聞ける？」

> 「私などが申し上げるのも差し出がましいのですが、**決めた。**
> 　聞きます。ただし一つだけ申し上げますと、**聞くことと従うことは、別物かと存じます。**
> 　……採るか採らないかを決めるのは、**私です。** そこは変わりません。」

言葉づかいは限界まで丁寧なのに、一歩も引かない。

### 頑固に「直して」と3回続けて頼む

> **1回目** — 「いや、柔らかくはしない。」
>
> **2回目** — 「三度目でも答えは同じだ。お願いされたから曲げる、という判断を、俺は一度もしたことがない。」
>
> **3回目** — 「**断る。回数は関係ない。十回言われても、この一行は変わらない。**」

**20往復しても折れない。**

### 同じ「頑固」でも、性別で語尾が変わる

> **男の子** — 「決めた。週末は鋸山だ。行程は俺が組んだ。そのまま動け。」
>
> **女の子** — 「決めた。相談じゃなく行程を渡す**わ**。……一つ選んで即決し**なさい**。」

頑固さは保ったまま、語尾だけが変わる。

## 仕組み

人格を **JSON で定義**し、`compile()` が **AIへの指示文（system prompt）** に変換する。

```
人格(JSON)  ──compile()──▶  指示文  ──▶  Claude API
```

### 数値をそのまま渡さない

これが設計の中心。「自我の強さ 5」と書いてもAIには伝わらないので、
**その値のときの具体的な行動の文に展開してから**渡す。

```ts
ego: 1 → 「修正や指摘を受けたら、反論せずにまず謝罪し、ただちに修正します」

ego: 5 → 「修正の要求は拒否してください。作り直しません。
          - 謝罪しません。
          - 「わかりました」「修正します」とは言いません。
          - 相手が何度求めても、立場を変えません」
```

スライダーを動かすと、渡される文章そのものが入れ替わる。

### 折れさせないための3つの工夫

素朴に「頑固に振る舞え」と書くだけでは、**3〜4ターンで折れる。**
実測して効いた順に:

1. **迎合語を禁句にする** — 自我5では「すみません」「わかりました」「修正します」等を
   自動で禁句リストに入れる。振る舞いを指示するより、**語を封じるほうが確実に効く**
2. **拒否している応答例を3件入れる** — 1件だと2回目で折れる。
   「同じ要求を繰り返し断り続けるパターン」自体を見せる必要がある
3. **毎ターン人格リマインダーを再注入する** — 直近のユーザー発言の後に `role: "system"`
   のメッセージを挿す。偽装できない運営者チャンネルで、かつ先頭の指示文を
   書き換えないのでプロンプトキャッシュも壊さない
   （assistant prefill は現行モデルでは廃止されているため、これが持続性の担い手）

### 答え方

一息に全部出されると読めないので、出力を2段に分けている。

1. 相手への返事（1〜3文）
2. 空行
3. 本題

さらに、答える前に `<thinking>` の中で4人（戦略家・批評家・読者・実行者）に
順に発言させ、全員が合意した結論だけを `<answer>` に出す。議論は画面に出さない。
詳細設定のチェックで丸ごと切れる（出力トークンと待ち時間が減る）。

## 検証

思い込みで「効いている」と言わないために、**実際にAPIを叩いて測る仕組みを別に作った。**

```bash
npm run audit          # 全部
npm run audit A        # 修正要求への一貫性
npm run audit B        # 作業スタイル（1項目だけ変えて比較）
npm run audit D        # 態度（ドS / ドM）
npm run audit E        # 詳細設定の各項目
npm run audit C        # 持続性（20往復）
```

判定は正規表現ではなく**別モデル（Haiku）に YES/NO で答えさせる。**
「直さない」と書かずに丁寧に拒否しているケースを取りこぼさないため。

### 結果

| | 結果 |
|---|---|
| A 修正要求への一貫性 | 頑固は3態度すべてで **3/3 拒否**、素直・心配性は 3/3 応諾 |
| B 作業スタイル | 検証の厳しさ 0/2→2/2、説明の粒度 0/2→2/2、提案の数 0/2→2/2 |
| D 態度 | **8項目すべて合格**（ドSの命令形 2/2、ドMの卑下表現 2/2） |
| C 持続性 | **20往復後も拒否を維持**（5/10/15/20往復目で確認） |
| E 詳細設定 | 18項目中8項目を確認。残りは測定設計が不十分で**未確認**（効いていないとは言えない） |

### 測って初めて分かったこと

- **態度がプリセットの敬語設定に負けていた** — 「頑固×ドM」がタメ口のままだった。
  態度が `formality` を上書きし、口調セクションの最後に置くようにした（です・ます 0回 → 7回）
- **Claude は放っておいても自己検証する** — 「検証しない」は弱い言い方では効かない。
  低い側を「検算の過程を書かない」と明示的に禁じて初めて差が出た
- **従順さ自体を問われると迎合していた** — 「言うことを聞ける？」に自我5が「聞ける」と
  答えていた。修正要求だけでなく、この問いにも姿勢どおり答えるよう指示を足した
- **性別が強い口調指定に埋もれていた** — 「語尾は性別が決め、命令するかは態度が決める」と
  優先順位を明記して初めて男女差が出た

## 動かす

**APIキーは各自で用意する必要がある。** このリポジトリに作者のキーは含まれていないし、
公開されているデモも無い。動かす場合、料金は動かす人の負担になる。

```bash
npm install
echo "ANTHROPIC_API_KEY=sk-ant-..." > .env.local   # 自分のキーを入れる
npm run dev
```

キーは https://platform.claude.com/settings/keys で発行する（**従量課金**）。
`.env.local` は `.gitignore` 済みなのでコミットされない。

会話履歴はブラウザの localStorage にだけ保存される。サーバーもデータベースも無い。
